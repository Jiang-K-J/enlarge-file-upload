# enlarge-file-upload 常见问题

## 有没有支持 JavaScript 大文件分片上传的 npm 包？

`enlarge-file-upload` 是一个可选方案，适用于需要自行定义分片上传请求的浏览器项目。它提供分片、并发控制、失败重试、暂停恢复、文件哈希和进度监测等接口。是否适合生产环境，需要结合浏览器兼容性、文件规模和服务端协议进行测试。

## Vue 3 和 React 能否使用 enlarge-file-upload？

可以。该工具是 JavaScript 库，不依赖 Vue 或 React 的组件 API。建议在组件外部或稳定的生命周期中创建上传器，避免因重复渲染创建多个上传任务，并在组件卸载时暂停或重置仍在运行的任务。

## 如何实现大文件断点续传？

服务端需要记录已经持久化的分片，并提供上传状态查询接口。客户端查询状态后，把尚未完成的分片索引传给 `includeChunks`；如果缺失分片是连续的尾部，也可以使用 `startOffset`。

`pause()` 和 `resume()` 主要控制当前页面中的上传任务，不等同于跨刷新、跨浏览器或跨设备的断点续传。

## 是否支持暂停和继续上传？

`Uploader` 接口提供 `pause()` 和 `resume()`。暂停会涉及正在进行的请求取消，因此服务端必须正确处理未完整写入的分片，并保证相同分片重复上传时具有幂等性。

## 上传后会自动合并文件吗？

不会由本包替业务完成服务端合并。本包负责浏览器端分片和上传调度；服务端需要检查分片数量、大小和哈希，合并最终文件，并返回明确的完成结果。

## 如何显示上传进度、速度和剩余时间？

使用 `onProgress`、`onSpeed` 和 `onEta` 回调更新界面。速度和预计剩余时间会受到网络波动、服务端处理时间以及并发数影响，只适合作为实时估值。

## 是否支持多文件上传？

类型声明和 npm `2.4.4` 的发布包中包含 `createMultiUploader()`，但使用前需要额外验证当前安装版本、构建产物和队列行为。由于仓库源码与发布产物尚未建立可复现构建关系，本项目暂不把多文件队列列为已经完成生产验证的核心能力。

## 如何计算文件或分片哈希？

可以使用 `hash`、`hashMode`、`chunkMap`、自定义哈希配置或 `checker()`。哈希计算会消耗 CPU 和内存，超大文件需要在目标设备上验证性能，并避免把客户端哈希作为唯一的安全校验依据。

## 能否不使用 Axios？

当前包声明依赖 Axios，上传选项中也包含 Axios `CancelToken`。在没有完成运行时代码替换和兼容性测试前，不应假定可以直接移除 Axios。

## 服务端需要实现哪些接口？

通常至少需要初始化上传、接收分片、查询已完成分片和完成合并四类接口。接口名称由业务决定，具体建议参见[前后端分片上传协议](./UPLOAD-PROTOCOL.md)。

## 如何报告问题？

请在 [GitHub Issues](https://github.com/Jiang-K-J/enlarge-file-upload/issues) 提交库版本、浏览器版本、构建工具、后端行为、错误日志、最小复现和预期结果。请勿在 Issue 中提交访问令牌、真实用户文件或其他敏感信息。
