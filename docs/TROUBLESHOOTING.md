# enlarge-file-upload 常见错误与排查方法

## 提示缺少 uploadFunction

`uploadFunction` 是必填配置。它负责把单个分片发送到业务后端，本包不会自动生成上传地址或服务端接口。

检查是否在创建上传器时传入了返回 `Promise` 的函数：

```ts
const uploader = createUploader({
  uploadFunction: async ({ chunk, index }) => {
    // 将 chunk 和 index 发送到业务后端。
  },
});
```

## 客户端显示 100%，但服务端没有完整文件

客户端 100% 只表示计划中的分片请求已经完成，不代表服务端已经合并和验证最终文件。业务需要额外调用完成接口，并以该接口的结果作为最终状态。

## 页面刷新后无法继续上传

`pause()` 和 `resume()` 主要用于当前页面会话。跨刷新恢复需要服务端保存上传任务和已完成分片，页面重新打开后查询服务端状态，再将缺失索引传给 `includeChunks`。

## 暂停后服务端出现损坏分片

暂停可能取消正在传输的 Axios 请求。服务端应先写入临时文件，确认分片长度和哈希后再标记为完成；重复提交相同 `uploadId + index` 时必须保持幂等。

## 哈希计算耗时或占用内存较高

哈希性能与文件大小、设备 CPU、线程数量和 `hashMode` 有关。请在目标设备上测试，并根据业务需求决定是否计算完整文件哈希、分片哈希或关闭客户端哈希。服务端不能只信任客户端提交的哈希值。

## TypeScript 类型存在，但运行时找不到某个导出

先确认安装版本，并检查实际包中的 `dist/upload.js` 与 `index.d.ts` 是否对应。类型声明存在不代表当前构建产物一定包含相同导出。

GitHub 仓库中的 `dist/upload.js` 主要用于演示，不应据此判断 npm 安装包的运行时导出。请以实际安装版本为准，并通过导出冒烟测试确认 `dist/upload.js` 与 `index.d.ts` 相匹配。

## CDN 引入后找不到全局变量

不同历史构建的 UMD 全局名称存在不一致风险。在构建产物完成统一和验证前，优先使用 npm 安装与模块导入，不建议依赖未验证的 CDN 全局变量名称。

## 如何提交可诊断的问题？

请在 [GitHub Issues](https://github.com/Jiang-K-J/enlarge-file-upload/issues) 提供：

- `enlarge-file-upload` 版本
- 浏览器、框架和构建工具版本
- 最小复现代码
- 服务端确认的分片状态
- 脱敏后的错误信息和预期行为

不要提交访问令牌、真实用户文件、内部服务器路径或其他敏感信息。
